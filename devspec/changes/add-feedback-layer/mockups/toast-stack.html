The toast surface is --popover / --popover-foreground / --border — identical to the existing dropdown-menu, so a toast and the user menu read as the same material. Tone appears in one place only: the icon — a flat, solid tone-filled shape with the glyph knocked out in the surface colour. No coloured rail, no tinted background, no coloured edge. This is why sonner’s richColors was rejected: it floods the whole surface and stops matching the app.

C · the two tokens this change adds
Token:root (light).darkWhy this value
--success oklch(0.58 0.14 157) oklch(0.72 0.16 157) Same lightness pair as --destructive (0.577 / 0.704), so the tones sit at one visual weight.
--warning oklch(0.70 0.15 75) oklch(0.80 0.15 80) Lighter than the others on purpose — amber at L 0.58 reads brown, not warning.

Neither token gets a --*-foreground pair. Tone never fills a surface here, so nothing is ever laid on top of these colours. Add the pair the day a success Button variant exists.
