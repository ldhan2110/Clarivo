# Context: Clarivo

**Does**: Turns meeting conversations into clear, structured, actionable software requirements. A BA-facing tool: create a project, give it context documents, get an AI-suggested discovery/meeting plan, run meetings (transcript + AI analysis), then land the output in a requirements repository with conflict/gap detection and traceability back to the meeting that produced each requirement.

> The prose above is derived from the product mockup `assets/ChatGPT Image Sep 30, 2026, 02_57_53 PM.png` (15-screen MVP board) — not from code. Both READMEs are untouched framework boilerplate. Correct this paragraph if it misses the mark.

**Stage**: early. Backend is foundation-only — config, error envelope, base entity, shared DTOs. **Zero domain entities, zero migrations, zero controllers.** Frontend is scaffold-only — one page, one UI component, API client + query provider wired.

**Stack**
- Backend: NestJS 12 + TypeORM 1.1 + Postgres 17 (CommonJS, TS 6, `strict`), class-validator/class-transformer, Swagger (`@nestjs/swagger` + CLI plugin)
- Frontend: Next.js 16 (App Router, RSC) + React 19 + Tailwind v4 + shadcn/ui (new-york, slate) + TanStack Query 5 + Axios
- Infra: `docker-compose.yml` at repo root — Postgres only, host port from `DATABASE_PORT` (5437; 5432 is taken by a native install)
- Package manager: pnpm. **Two separate projects, not a workspace** — `backend/` and `frontend/` each have their own `package.json`, lockfile and `pnpm-workspace.yaml`.

**Structure**
```
backend/src/
  main.ts                 bootstrap: CORS, ValidationPipe, filter, Swagger
  app.module.ts           ConfigModule(validate) + TypeOrmModule
  config/                 env.validation.ts (the env contract), database.config.ts
  common/                 dtos/ (AuditDto, PaginationDto, SortDto) + exceptions/
  database/               base.entity.ts, data-source.ts (CLI), migrations/ (empty)
  filters/                app-exception.filter.ts
frontend/app/             ALL frontend code lives under app/ — no src/
  layout.tsx page.tsx globals.css
  components/ui/          shadcn components (button only)
  components/provider/    query-provider.tsx
  lib/                    api.ts (axios), utils.ts (cn)
  types/api/              GENERATED by openapi-ts — never hand-edit
```

**Entry points**
- Backend: `backend/src/main.ts:9` (`bootstrap`); TypeORM CLI: `backend/src/database/data-source.ts:4`
- Frontend: `frontend/app/layout.tsx:21` (RootLayout), `frontend/app/page.tsx`

**Build / test / run**
| | backend/ | frontend/ |
|---|---|---|
| install | `pnpm i` | `pnpm i` |
| run | `pnpm start:dev` | `pnpm dev` |
| build | `pnpm build` | `pnpm build` |
| test | `pnpm test` (vitest) · e2e `pnpm test:e2e` | none configured |
| lint | `pnpm lint` (oxlint) | `pnpm lint` (eslint) |
| db | `pnpm db:up` / `db:down` | — |
| migrations | `migration:generate` / `:run` / `:revert` / `:show` | — |
| api types | — | `pnpm api:types` (needs backend up) |

**⚠ Port collision**: backend `PORT=3000` and `next dev` both default to 3000. Next auto-bumps to 3001, which `CORS_ORIGINS` does **not** list — browser calls from the frontend will fail CORS. `backend/.env` currently allows `:3000` (itself) and `:5173` (dead Vite leftover).
