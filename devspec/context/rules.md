# Rules

## Don't touch
- `frontend/app/types/api/**` — generated by `pnpm api:types`. Regenerate, never hand-edit.
- `backend/dist/`, `.next/`, `node_modules/`, `*.tsbuildinfo`.
- Applied migrations under `backend/src/database/migrations/` — add a new one, never rewrite one that has run.
- `backend/.env`, `frontend/.env.local` — gitignored, real secrets. Changes to the env contract go in `.env.example` **and** `env.validation.ts`.

## Before merge
- `backend/`: `pnpm lint` && `pnpm test` && `pnpm build`.
- `frontend/`: `pnpm lint` && `pnpm build` (no tests exist).
- Schema change: `pnpm migration:generate` → read the generated SQL → `pnpm migration:run`. `synchronize` is **false in every environment** (`backend/src/config/database.config.ts:25`); the schema only ever changes through a migration.
- Backend API change that the frontend consumes: rerun `pnpm api:types` in `frontend/` with the backend running.

## Security
- `whitelist` + `forbidNonWhitelisted` are on globally — an undeclared request field is a 400, not silently dropped. Keep it that way.
- A field without `@Expose()` never leaves the server. Secrets (password hashes, tokens) must have no `@Expose()` and must not be added to any response DTO.
- `AppExceptionFilter` deliberately replaces non-HTTP exception messages with `'Internal server error'` (`backend/src/filters/app-exception.filter.ts:71`) — don't "improve" it into leaking internals.
- Env vars are validated at boot and the process dies on a bad one. Don't add `?? 'default'` fallbacks at the call site to work around a missing var.

## Gotchas
- **Port collision**: backend `PORT=3000`, `next dev` also wants 3000 and silently bumps to 3001 — which `CORS_ORIGINS` doesn't allow. Pin the frontend port and fix `CORS_ORIGINS` before debugging any "random" CORS failure.
- **Postgres is on 5437**, not 5432 — 5432 is held by a native install. Comes from `DATABASE_PORT` via `docker-compose.yml`.
- **The container's superuser is `clarivo`, not `postgres`** — the volume predates the current compose file. A fresh volume and this one will not agree; if auth fails, check which role actually exists before changing `.env`.
- **Backend is CommonJS.** ESM-only packages and top-level `await` break the build. Vitest configs must stay `.mts`.
- **Boolean env vars need care**: `enableImplicitConversion` already coerced the value, and `Boolean('false')` is `true` — the `SWAGGER_ENABLED` transform reads the raw string off `obj` for this reason (`backend/src/config/env.validation.ts`). Copy that shape for any new boolean.
- **The shadcn CLI hangs** in this environment (stalls at "Installing dependencies"). Copy component source by hand into `frontend/app/components/ui/`.
- **No migrations have ever run** beyond the empty `migrations` table — the first real entity also first-exercises the whole generate/run pipeline. Budget for friction there.
- **Swagger declares `addBearerAuth()`** (`backend/src/main.ts:33`) while the frontend Axios client sends cookies (`withCredentials: true`). These two disagree; whichever auth transport lands first must fix the other.
- `pnpm migration:*` scripts **build first** and run against `dist/` — a compile error shows up as a confusing migration failure.
